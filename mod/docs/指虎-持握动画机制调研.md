# 指虎：持握/挥击动画机制调研（2026-10-18）

> 目标：搞清"角色为什么这样拿指虎"，以及**能不能给指虎加一套自己的动作**（比如握拳姿势 / 指虎专用挥击）。
> 全部结论来自本机解包实测（Divine 解包 Shared.pak + 逐个 lsf 转 lsx 检查）。

---

## 一、结论速览

| 问题 | 答案 |
|---|---|
| 武器的**持握/待机姿势**能在数据里指定吗 | **不能**。`Weapon.txt` 的 42 个字段、RootTemplate 的完整节点树、VisualBank 条目，三处都没有任何动画字段 |
| 武器的**攻击动画**能指定吗 | **能**，而且是逐法术的：`SpellAnimation`（主手）+ `DualWieldingSpellAnimation`（双持/副手）。指虎现在用徒手出拳动画 |
| 游戏里"武器 → 动画套"是数据驱动的吗 | **是**，但映射表在数据里，**选择逻辑在引擎里** |
| 能给指虎加一套全新动作吗 | **部分能**：能新增动画集，但**没法让某件武器去选它** —— 除非重映射已有原型（会波及同类武器） |
| "两只手各一只"能做到吗 | 引擎的常规做法是**两件物品双持**；`Twohanded` 只会变成"两只手握一件" |

---

## 二、动画系统在哪些文件里

解包 `Shared.pak` 后找到三处关键资源：

```
Public/Shared/WeaponAnimationSetData/WeaponAnimationSetData.lsx    17,916 B
Public/Shared/Content/Assets/Weapons/[PAK]__Anims/_merged.lsf      491,651 B
Public/Shared/AnimationOverrides/AnimationSetPriorities.lsx        11,479 B
```

### 1. `WeaponAnimationSetData.lsx` —— 主/副手原型 → 动画集

每条记录三个字段：

```xml
<node id="WeaponAnimationSet">
    <attribute id="AnimationSetUUID" type="FixedString" value="1a1b8d62-..."/>
    <attribute id="MainHand" type="FixedString" value="Piercing1H"/>
    <attribute id="OffHand"  type="FixedString" value="Piercing1H"/>
    <attribute id="UUID" type="guid" value="89a09a14-..."/>
</node>
```

- **20 种武器动画原型**：`Small1H`(11) `Piercing1H`(10) `Slashing1H`(10) `Javelin1H`(10) `Shield1H`(5)
  `Crossbow1H`(3) `Bow2H` `Crossbow2H` `Generic2H` `Polearm2H` `Sling1H` `Spear2H` `Staff2H` `Sword2H`
  `Voice` `Drum1H` `Flute1H` `Lute1H` `Lyre1H` `Violin1H`
- 63 条组合记录，指向 **34 个不同动画集 UUID**
- 注意 `Small1H` 出现最多 —— 单手小武器（含钝击轻武器）都走它

### 2. `[PAK]__Anims/_merged.lsf` —— 动画本体

转成 lsx 后 1.27 MB，包含五个 bank：

```
AnimationBlueprintBank / SkeletonBank / PhysicsBank / AnimationSetBank(26) / AnimationBank(84)
```

结构是四层嵌套：`Resource > AnimationSet > AnimationBank > AnimationSubSets > Object(MapKey) > Animation`。
`Object` 的 `MapKey` 是动画事件名（攻击/待机/受击等），`Animation` 指向 `AnimationBank` 里的资源。

### 3. `AnimationSetPriorities.lsx` —— **与武器无关**

内容是 `Rage` / `RecklessRoar` / `Fury` / `Githyanki_Parry` / `Holding_Mug` / `Class` 这类
**角色与职业**动画集的优先级表，不是武器原型表。（一度以为是最后一块拼图，实测排除。）

---

## 三、缺的那一环：武器 → 原型

把"Small1H / Slashing1H / Piercing1H …"这些字符串在**全部** stat 文件与全部 RootTemplate 里搜，
**只在 `WeaponAnimationSetData.lsx` 里出现**。

⇒ 结论：**引擎自己按武器类别挑选原型**，具体键不在数据里。
从原型命名与武器分类推断，键大概率是「`Weapon Group` × `Weapon Properties`」的组合
（单/双手、伤害性质、是否乐器等），但无法通过数据确认，也无法通过数据覆盖。

---

## 四、那么"给指虎做一套自己的动作"能做到哪一步

### ✅ 能做：攻击动画（已验证生效，且已在用）

`SpellAnimation` / `DualWieldingSpellAnimation` 是**逐法术**字段，指虎的四个攻击法术都继承
了徒手出拳动画。这条**没有副作用**，也不会波及其它武器。

### ⚠ 能但代价大：重映射已有原型

既然不能"让武器选新原型"，唯一可落地的改法是**把某个原型组合指向一套自定义动画集**：

1. 在 `[PAK]__Anims` 里新增 `AnimationSet`（用徒手出拳的 Animation 资源拼）
2. 在 `WeaponAnimationSetData.lsx` 里把**我们武器实际落入的那个 `(MainHand, OffHand)` 组合**
   改成指向这套新 UUID

**代价**：所有落入同一组合的武器会一起变。例如若指虎落在 `(Small1H, 空)`，
那么所有单手小武器（棍、锤、手斧…）都会跟着变成握拳姿势。
这类全局副作用需要一个专门的分支版本去试，不能直接进主力包。

### ❌ 做不到

- 让"这一件武器"单独拥有新动作（数据层没有这个键）
- 改变**持握/待机**姿势（没有任何可写字段；能改的只有动画集，而动画集不覆盖持握姿态）

---

## 五、"双手武器"这一条的现实

`Twohanded` 的效果是：**占用两只手、用双手握持原型（Generic2H 一类）**。
对指虎来说，这意味着**一只指虎被两只手握着** —— 视觉上不会变成"左右手各一只"。

"左右手各一只"在引擎里的原生实现只有一条：**两件物品、双持**。
之前实现过的 `CastOffhand`（主手攻击自动带副手一击）+ `DualWieldingSpellAnimation` 正是为此，
但按用户要求已回退。

若将来要再走这条路，需要额外解决**手性**：副手件必须是镜像网格（掌条朝手心、刺面朝外这两件事
在左手上要重新成立），而不是同一份模型换个槽位。

## 六、下一步可试的（按代价排序）

1. **零代价**：确认当前 `Twohanded` 版本在游戏里的实际观感（是否接受"两只手握一件"）。
2. **低代价**：新建一个独立分支 pak，只改 `WeaponAnimationSetData.lsx` 的一行，
   把 `(Small1H, 空)` 或 `(Generic2H, 空)` 指向一套用徒手动画拼的自定义 AnimationSet，
   观察指虎姿势是否变化、以及波及了哪些武器。**不进主力包**。
3. **中代价**：若第 2 步证明可行，再做一套"指虎专用"动画集（握拳待机 + 直拳/勾拳攻击），
   用同样的重映射挂上去。
4. **高代价 / 不推荐**：两件双持 + 镜像件（需要重做 3 件镜像模型与 3 组 stats/模板）。
