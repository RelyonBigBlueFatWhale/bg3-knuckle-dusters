# 指虎：持握姿势与骨骼绑定调研（2026-10-18）

> 目的：搞清"角色为什么这么拿指虎"以及"要让姿势正确，能改哪个字段"。
> 全部结论都在本机实测过（解包原版数据 + 干跑打包链），下面按"已验证 / 未验证"标注。

---

## 一、结论速览（先看这个）

| 问题 | 答案 |
|---|---|
| 角色持握姿势由什么决定？ | **由 `Weapon Group` + `Weapon Properties` 推导出的武器类别**，引擎据此选择一整套持握/挥击动画。**游戏里没有"拳套"专用持握姿势**，最接近的是"单手轻型近战"。 |
| 攻击时用哪套动作？ | **每支法术自己的 `SpellAnimation`**。我们的主手攻击继承 `Target_UnarmedAttack`（出拳）；三支疾风连击变体各自带武僧动画。**这两处我们都没动过，所以是原版的拳击动作。** |
| 网格怎么贴到手骨上？ | **刚性绑定**：GR2 内置骨链 `Dummy_<stem>` → `Dummy_Sheath` → `Dummy_Attachment` → `Dummy_FX/_01/_02` + `<stem>_Mesh`；握把点 = `Dummy_Attachment` 世界坐标。**不需要蒙皮权重、不需要人物骨架**。 |
| 那"姿势不对"能改什么？ | 只能改**网格相对 `Dummy_Attachment` 的平移/旋转**（`pack_gr2.py` 的 `ATTACH_WORLD` 与 `KD_OFF_X/Y/Z`）。姿势本身改不了。 |

## 二、三条链路逐一实测

### 1. RootTemplate（`Public/KnuckleDusters/RootTemplates/_merged.lsx`）—— **姿势不在这里**

我们的三个模板只有 7 个字段：

```
EquipmentTypeID = 2d85d633-d496-44a1-a643-0e95ef879a6d   ← 与原版匕首完全相同
ParentTemplateId = 569b0f3d-abcd-4b01-aaf0-979091288163  ← 与原版武器相同
PhysicsTemplate / VisualTemplate / Stats / Icon / Type
```

对比原版 `WPN_HUM_Dagger_A_1`（从 40 MB 的 `Public/Shared/RootTemplates/_merged.lsf` 挖出来的完整节点）：
**字段集完全相同**，它也只是多了 `CanShootThrough / Flag / IsInspector / LevelOverride / Race / ReadinessFlags / Tooltip / WalkThrough` 这些与持有姿势无关的字段。
⇒ **RootTemplate 里没有任何动画/持握字段。改它解决不了姿势。**

### 2. VisualBank（`wire_visuals.py` 生成）—— **也不是这里**

原版武器视觉条目（`WPN_HUM_Glaive_A_2_Poison`）里，与骨骼相关的三个字段全是空：

```
AttachBone = (空)     SkeletonResource = (空)     SkeletonSlot = (空)
```

我们的条目同样留空 ⇒ 与引擎约定一致，**不需要填**。

### 3. Stats（`Weapon.txt` 字段全集）—— **姿势的实际来源**

把原版所有武器条目的字段名做成全集，与"动画/持握"相关的只有两个：

```
Weapon Group        值域只有 4 个：SimpleMeleeWeapon / SimpleRangedWeapon / MartialMeleeWeapon / MartialRangedWeapon
Slot                值域含 "Melee Main Weapon" / "Ranged Main Weapon"
Weapon Properties   22 个固定值（Light / Twohanded / Heavy / Finesse / Reach / Melee / Dippable / Magical / Torch …）
```

- 我们的武器 `using "_BaseWeapon"`，而 `_BaseWeapon` 已经写了
  `Weapon Group = SimpleMeleeWeapon`、`Slot = Melee Main Weapon` ⇒ **已继承，不需要重复写**。
- 我们这一轮把 `Weapon Properties` 从 `Melee;Twohanded;Dippable;Magical` 改成了
  `Melee;Dippable;Magical;Light` —— **去掉 Twohanded 是关键**：双手武器会走双手握姿，
  拳套显然不该。`Light` 让它落到"单手轻型"那一档。
- 另有一个 `WeaponFunctors` 字段（原版仅 1 处使用，如火把的 `GROUND:IF(...):SurfaceChange(Ignite)`），
  是"武器自身携带的 functor"，与持握姿势无关，但**可以**用来放命中效果（本次剥壳改用
  `StatsFunctorContext "OnDamage"` 的被动，没走这条路）。

### 4. 攻击动画：`SpellAnimation`

| 法术 | 动画来源 | 现状 |
|---|---|---|
| 主手攻击 `Target_KD_Attack*` | 继承 `Target_UnarmedAttack` | **出拳动画** ✓（我们没覆盖 `SpellAnimation`） |
| 疾风连击三支变体 | 各自带 `SpellAnimation`（例如推击 `e1a544d9-…;c06d3974-…`） | **武僧连击动画** ✓（我们只改了 `SpellSuccess`/`SpellFlags`） |
| 武艺：徒手打击 | 继承原版 | 原样 ✓ |

⇒ **动作观感是原版的，这点没问题**；用户看到的"姿势不对"只可能是网格在手里的位置/朝向。

## 三、骨骼绑定链路（已实现，本轮干跑复验通过）

```
model_out\<name>.obj
   │  pack_gr2.py：按 map_pos 把 Blender 坐标映射到原版匕首 DAE 的骨链
   ▼
gr2_convert\v7\<name>.dae        （骨架模板来自原版 s\skeleton\dagger.dae）
   │  divine -a convert-model
   ▼
gr2_convert\v7\<name>.gr2        （头 e5 9b 49 5e）
   │  preprocessor Decompress → 校验骨名
   ▼
七骨链：Dummy_<stem> / Dummy_Sheath / Dummy_Attachment / Dummy_FX / _FX_01 / _FX_02 / <stem>_Mesh
```

**本轮新模型干跑结果（未部署）**：

| 件 | 三角面 | DAE | GR2 | 七骨链 |
|---|---|---|---|---|
| 钢刺之拳 | 8,668 | 4.14 MB | 693,404 B | 完整 |
| 彻骨之寒 | 9,374 | 4.49 MB | 748,468 B | 完整 |
| 无锋 | 10,000 | 4.79 MB | 797,300 B | 完整 |

⇒ **换成多视角重建的新网格，打包链不需要任何改动。**

握把点的依据（前次实测）：原版匕首的握柄截面中心 z=+0.0710，`Dummy_Attachment` z=+0.0680，
**相差 3 mm** ⇒ "握柄中心 = `Dummy_Attachment`" 是原版约定。我们的网格原点就被映射到该点。

## 四、要"姿势正确"，实际能动的三个旋钮

1. **轴向平移** `KD_OFF_X / KD_OFF_Y / KD_OFF_Z`（米，游戏坐标，`pack_gr2.py` 读环境变量）
   - 前后（沿手臂方向）、上下、左右各 ±2 cm 足够覆盖。
2. **90° 旋转方向**：`map_pos` 里现在是 `collada = (-Zb, Xb, -Yb)`；若进游戏发现孔排方向反了，
   把符号翻成 `(Zb, -Xb, -Yb)` 即可（两个方向都试过，一次改动即出）。
3. **网格原点**：目前三件统一为包围盒中心（已验证 `(0,0,0)` 偏差 0.0000 mm）。
   若想把"四孔那一排的中心"对齐手骨，需要按孔位重新定位原点 —— 这一步要等贴图/模型定稿后再做，
   否则每次重导都要跟着改。

---

## 五、结论与下一步

- **姿势改不动，位置可以**：引擎没有"拳套持握姿势"，我们能控制的只有网格相对手骨的位置/朝向。
  当前配置（SimpleMeleeWeapon + Light + 非双手）已经是可用的最优档。
- **动作是原版的**：主手出拳、疾风连击用武僧连击动画，均未被我们的改动破坏。
- **待办**：
  1. 贴图定稿后打包新模型 → 进游戏看"手是不是正好套在孔里"，用 `KD_OFF_*` 微调（预期 1–3 轮）。
  2. 若希望连"待机时手是握拳"也做出来，唯一办法是给**角色骨架**做自定义姿势覆盖（需要动画替换，
     不在 stat 层，成本高、且会与其它武器冲突）—— 不推荐。
