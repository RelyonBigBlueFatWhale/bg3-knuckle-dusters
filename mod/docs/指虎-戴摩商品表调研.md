# 戴摩（Dammon）商品表网络调研 + 反查结果（2026-10-18）

> 目标：搞清"指虎怎么进戴摩各章货架"，且**不污染**原版数据。
> 手段：bg3.wiki 文档 + 本地解包 Gustav.pak 反查（用户提供的三章独特物品用来定位）。

---

## 一、结论速览

| 问题 | 答案 |
|---|---|
| 有没有"追加"语法 | **有**：`CanMerge 1`。bg3.wiki 的 `Modding:Items` 页**明文示范**这个写法（"This will make it spawn in the tutorial chest"） |
| 同名覆盖 vs CanMerge | 同名 `new treasuretable` = **整表替换**（会丢原版行，= 污染）；`CanMerge 1` + 只写自己的 subtable = **追加**（不动原版） |
| 戴摩三章的表 | 三张都存在，但**分在两个数据层**（见下） |
| 二三章会带上一章的货吗 | **会**：`HAV_` 与 `LOW_` 里都有 `object category "T_DEN_Weaponsmith_Trade"` —— 所以第一章的货在二三章继续卖（wiki 原话："Act One 的商品三章都能买到"） |
| 章节差异从哪来 | 每章**各自追加**独特物品 + `StartLevel` 等级门 + 通用 `T_ST_Generic_Magic_*_ACT2_A` 子表 |

## 二、三张表的真身（逐层核对）

| 章节 | 表名 | 所在数据层 | 用户给的独特物品 | 表里对应的模板 |
|---|---|---|---|---|
| 第一章 | `DEN_Weaponsmith_Trade` | **Public/Gustav**（511 张表） | 狩猎短弓 | `I_MAG_Hunting_Shortbow`（`new subtable "-1"` 保底） |
| 第二章 | `HAV_Weaponsmith_Trade` | **Public/GustavDev**（539 张表） | 偷生之剑 | `I_MAG_FlamingFist_Longsword` 等（表内含 `T_DEN_Weaponsmith_Trade`） |
| 第三章 | `LOW_Weaponsmith_Trade` | **Public/GustavDev** | 坚毅之甲 | `I_MAG_EndGame_Plate_Armor`（= Armour of Persistence） |

> 附：`Public/Honour` 只有 7 张表、`Public/Shared` 446 张 —— 都不含戴摩表。
> 我先前判断"HAV_/LOW_ 不存在"是**只解了 Gustav 一层**，这是错的，已纠正。

### 第一章表结构（节选）

```ini
new treasuretable "DEN_Weaponsmith_Trade"
new subtable "-1"                          // 保底
object category "I_MAG_Hunting_Shortbow",1,0,0,0,0,0,0,0
new subtable "-1"                          // 保底
object category "I_MAG_Safeguard_Shield",1,0,0,0,0,0,0,0
new subtable "1,1"                         // 掷 1 次
object category "T_EquipmentTrader_BodyArmor_Magic",1,0,0,0,0,0,0,0
...
```

### 第二章把第一章整张表包进来了

```ini
new treasuretable "HAV_Weaponsmith_Trade"
new subtable "1,1"
object category "T_DEN_Weaponsmith_Trade",1,0,0,0,0,0,0,0    // ← 第一章的货
new subtable "1,1"
```

## 三、subtable 语法（wiki 权威解释）

`new subtable "次数,权重;次数,权重;..."`

- 每个 `X,Y` = 「以权重 Y 掷出 X 次」
- 例：`"10,1;11,1;12,1;13,1"` → 等概率掷 10/11/12/13 次
- `"1,1"` = 掷 1 次
- `"-1"` = 保底 1 次（原版大量用于"必卖独特物品"）
- `object category` 前缀：**`I_`** = 物品模板名、**`T_`** = 引用另一张表
- 第二个数字是**同表内权重**（多物体时按权重抽）

**这不是等级区间**（我先前猜错过）。

## 四、两条可落地路线（都基于 CanMerge，均不覆盖原版行）

### 路线 1：三章都能买到（推荐）

只改一张表：

```ini
new treasuretable "DEN_Weaponsmith_Trade"
CanMerge 1
new subtable "-1"
object category "I_KD_SteelSpikeFist",1,0,0,0,0,0,0,0
new subtable "-1"
object category "I_KD_BoneChill",1,0,0,0,0,0,0,0
new subtable "-1"
object category "I_KD_Unsharpened",1,0,0,0,0,0,0,0
```

因为 `HAV_`/`LOW_` 都 `T_` 引用了 `DEN_`，**三章货架自动都有**，且原版行一个字节都没动。

### 路线 2：按章节解锁（各章上一件）

```ini
new treasuretable "DEN_Weaponsmith_Trade"   → 钢刺之拳
new treasuretable "HAV_Weaponsmith_Trade"   → 彻骨之寒
new treasuretable "LOW_Weaponsmith_Trade"   → 无锋
```

三张表各 `CanMerge 1` + 一条 `new subtable "-1"`。
这也是之前那版的做法，**结构是对的**，只是当时未验证。

## 五、待验证项（一次进游戏即可）

1. `CanMerge 1` 在本作是否真的合并（rather than 被忽略）—— 判据：戴摩原货（狩猎短弓、守护盾）**仍在**且指虎**同时**出现。
2. 保底写法用 `"-1"` 还是 `"1,1"` 更稳 —— wiki 用 `"1,1"` 说"always spawn"，原版保底用 `"-1"`。两者都可试，**先用 `"-1"` 对齐原版**。
3. 刷新时机：商人库存随**长休 / 升级**刷新，且按"首次与他交易的队友等级"掷表 —— 所以测的时候先长休一次再看。
